## 3. Failure incident (Day 01) — keep for interviews

### Symptom
```
NodeCreationFailure: Unhealthy nodes
aws-node: CrashLoopBackOff (1/2), 13 restarts
nodes: NotReady (kube-proxy Running — no ENI needed)
coredns: Pending
list-addons: []
```

### Root cause (chain)
1. Bootstrap self-managed CNI active; managed add-on never created (blocked on node group).  
2. `aws-node` had **no IRSA** (`AWS_ROLE_ARN` empty) and node role **had no CNI policy**.  
3. IPAMD could not call EC2 ENI APIs → no pod IPs → network plugin not ready → NotReady → EKS `CREATE_FAILED`.

### Recovery sequence (worked)
1. Confirm logs / describe pod / list-addons / describe-nodegroup.  
2. Fix `depends_on` in Terraform.  
3. `terraform apply -target=module.eks.aws_eks_addon.vpc_cni` — create managed CNI+IRSA **first** (targeted apply; warning: incomplete plan — only for recovery).  
4. Full `terraform apply` — node group **tainted** → destroy (8m) → create (1m47s) → kube-proxy + coredns created.  
5. Verify: nodes Ready, aws-node 2/2 with IRSA env, add-ons ACTIVE.

### Lesson
**Identity (IRSA) + order (add-on before nodes) both required.** Fixing only one still fails.

## 6. Trade-offs (lab vs production HA)

| Decision | Lab choice | Production HA alternative |
|----------|------------|---------------------------|
| NAT Gateway | **1×** shared (cost) | 1 NAT per AZ + per-AZ private RT |
| API endpoint | Public + private, IP /32 allowlist | Private-only + VPN/bastion + tighter CIDR |
| Nodes | 2× t3.medium on-demand | 3+ across AZs, mix spot/on-demand, larger |
| CNI permissions | IRSA only (not on node role) | Same — keep IRSA; never blanket CNI on all nodes |
| Control plane | EKS managed | Same (managed) |
| State | S3 + native lockfile (no DynamoDB) | Same pattern OK at this scale |
| Single NAT SPOF | Accepted for cost | Multi-AZ NAT for egress HA |
| Add-on conflict | `OVERWRITE` on create/update | Prefer `NONE`/`PRESERVE` once stable, pin versions |

**Approx ongoing cost after today (order of magnitude, ap-south-1):**  
EKS CP ~$73/mo + 2× t3.medium ~$60/mo + EBS ~$3/mo + existing NAT ~$32+/mo + EIP IPv4 ~$3.6/mo ≈ **~$170+/mo** while cluster runs.  
**Destroy impact:** `terraform destroy` on EKS deletes cluster/nodes (node disk data lost); VPC/NAT are separate — do not destroy casually.

## 7. Interview talking points (Day 01)

1. **Why IRSA for VPC CNI?** Least privilege: only `aws-node` gets ENI permissions; nodes keep baseline (join + ECR pull).  
2. **Why add-on before node group?** With split IAM, nodes must not join before CNI can authenticate via IRSA.  
3. **NotReady vs CrashLoopBackOff:** kubelet up but CNI/pod network not ready vs container restarting.  
4. **kube-proxy Running while aws-node fails:** hostNetwork vs needs ENI/pod IPs.  
5. **Pod IP vs node IP:** IPAMD secondary IPs on ENI; node IP is instance primary.  
6. **Single NAT trade-off:** cheaper, egress SPOF; pod↔pod still multi-AZ inside VPC.  
7. **busybox wget TLS fail ≠ broken API:** verify with `nc` TCP first; TLS is client/CA/SNI.  
8. **Tainted node group after CREATE_FAILED:** failed create often requires destroy+replace, not in-place fix.  
9. **Targeted apply:** recovery only; plan may be incomplete — always follow with full plan/apply.  
10. **Endpoints deprecation:** `kubectl get endpoints` warns v1.33+ → use EndpointSlice.
